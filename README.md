# win-iso-updater

[English](README.en.md)

**فلاشة ويندوز قديمة تدخل — ISO محدَّث يطلع. بأمر واحد.**

سكربت Python واحد (682 سطراً، ما يحتاج غير `requests`): يلقى ملفات التثبيت، ينزّل آخر Cumulative Update من كتالوج مايكروسوفت، يدمجه في الصورة، ويطلّع ISO يقلع على UEFI و BIOS.

كتبته وأنا أعيد تهيئة أسطول 1,800 جهاز في 3 شهور — ما فيه إدارة مركزية، جهاز بعد جهاز.

---

## المشكلة

دمج التحديثات جوّه صورة ويندوز اسمه *slipstreaming*. الفكرة معروفة، بس تسويها بيدك شي متعب.

الخطوات: تقرأ رقم الـ build، تدوّر في الكتالوج، تنزّل، تركّب `install.wim`، تدمج، تنظّف الـ components، تبني ISO. كل خطوة تنكسر بطريقة مختلفة.

الأداة هذي تسويها كلها بأمر واحد.

---

## كيف يشتغل

| الخطوة | الوظيفة |
|---|---|
| 1. يلقى ملفات التثبيت | يدوّر في كل الأقراص على مجلد `sources` فيه `install.wim` أو `install.esd` |
| 2. يجهّز الصورة | يحوّل `ESD` إلى `WIM` تقدر تعدّل عليه، ويقرأ رقم الـ build من داخلها |
| 3. يدوّر | يسأل Microsoft Update Catalog عن آخر Cumulative Update لهذا الـ build |
| 4. ينزّل | `aria2c` أول شي لو كان مثبت، وإلا تنزيل متوازي داخلي عبر HTTP Range على 8 اتصالات، وآخر حل اتصال واحد |
| 5. يدمج | `DISM` يركّب الصورة ويدمج `.msu`/`.cab` في **كل** إصدار جوّاها، وبعدها ينظّف الـ components |
| 6. يبني | `oscdimg` يطلّع ISO يقلع على UEFI و BIOS مع بعض |

الملف اللي نزل يبقى cache في مجلد التحديثات. التشغيلة الجاية تتخطّاه لو حجمه يطابق الحجم على السيرفر.

---

## أهم قرار في التصميم

خطأ `DISM 552` أكثر شي يوقّف العملية هذي: نسخة DISM على جهازك أقدم من الصورة اللي تشتغل عليها. رسالة ويندوز ما تقول لك كذا.

الأداة تفحص التوافق **قبل ما تبدأ** — تقارن build الـ DISM بـ build الصورة، وتوقف وتشرح لك وش تسوي (ثبّت ADK، أو مرّر `--dism`، أو تجاوز بـ `--force` على مسؤوليتك).

العملية طويلة — عشرات الدقائق. لو فشلت قرب النهاية، ترجع من الصفر. الفحص في البداية ما يكلّفك شي.

## التشغيل

```bash
pip install -r requirements.txt
```

```bash
# فلاشة موصولة: اكتشاف تلقائي وتحديث الوسط في مكانه
python iso_updater.py

# من ملف ISO جاهز، مع بناء ISO جديد
python iso_updater.py --no-detect --iso "D:\Win11.iso" --out "D:\Win11-Updated.iso"
```

| الخيار | الوظيفة |
|---|---|
| `--media` | تحدد جذر وسط التثبيت بنفسك (مثل `E:\`). الافتراضي: بحث تلقائي في كل الأقراص |
| `--no-detect` | يطفّي البحث التلقائي ويشغّل وضع الـ ISO |
| `--iso` | مسار ISO جاهز |
| `--out` | وين يطلع الـ ISO الناتج. بدونه يحدّث الفلاشة في مكانها |
| `--updates` | مجلد حزم التحديث. الافتراضي `<الفلاشة>\updates` يشتغل cache |
| `--connections` | كم اتصال تنزيل متوازي (افتراضي 8) |
| `--no-online` | ما يدوّر في الكتالوج — يدمج ملفات `.msu`/`.cab` المحلية بس |
| `--dism` | مسار `dism.exe` أحدث (مثل اللي يجي مع ADK) |
| `--force` | يتجاوز فحص توافق DISM (والغالب إنه يفشل) |

الأداة فيها 17 خياراً، والجدول يعرض أهمها. `python iso_updater.py --help` يوريك الباقي.

**يحتاج:** Python 3.9+ · Windows ADK (`DISM` + `oscdimg`) · صلاحيات Administrator

مثال للمخرجات (شلت طابع الوقت اللي يجي قبل كل سطر):

## لماذا بنيته

أشتغل مشرف تقنية معلومات. جاني أسطول 1,800 جهاز تتكرر فيه نفس المشاكل. ما فيه إدارة مركزية تصلحها عن بُعد، فالحل الوحيد كان إني أعيد تهيئتها كلها.

أخذت مني 3 شهور. في كل جهاز، أبطأ خطوة هي نفسها: يخلص تثبيت ويندوز، وبعدها تبدأ ساعات التحديثات.

فسويت الأداة هذي تدمج التحديثات جوّه الصورة مرة وحدة، عشان الجهاز يطلع محدَّث من أول إقلاع.

الأسطول طلع في الآخر مربوط بالإدارة المركزية وبلا مشاكله القديمة. بعدها بنيت نظام تجهيز بلا لمس (zero-touch provisioning)، عشان ما تتكرر تلك الشهور الثلاثة مرة ثانية.
